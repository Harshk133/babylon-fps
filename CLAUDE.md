# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Babylon FPS is a browser-based survival zombie FPS built with **Three.js**, **cannon-es**, **Vite**, and plain JavaScript ES modules. Do NOT migrate to React, Next.js, TypeScript, or Babylon.js unless explicitly requested.

## Commands

```bash
npm run dev       # Start dev server (http://localhost:5173)
npm run build     # Production build → dist/
npm run preview   # Preview the production build locally
npm run optimize-assets            # Build *.opt.glb / *.opt.jpg next to heavy assets in public/
npm run optimize-assets -- --force # Rebuild them all
npm run build-house-kit            # Pack public/models/house/source/** into house-kit.glb
npm run coop                       # Dev server on the LAN (vite --host); co-op relay at /ws
npm run coop:preview               # Same, but a production build
npm run relay                      # Standalone relay (PORT, default 8787) for hosting elsewhere
npm run android:sync               # vite build --mode android (.env.android: RELAY_URL) + cap sync
npm run android:apk                # ...then gradlew assembleDebug (needs JAVA_HOME = JDK 21, ANDROID_HOME)
```

No test runner is configured.

## Architecture

### Entry point

`src/main.js` — monolithic file containing the render loop, physics world, player, camera, input, animation, lighting, and world-asset loading. It is intentionally large; modularize incrementally, not all at once.

### Monster system (`src/zombies/`)

Most monsters are the Quake 2 MD2 player models from the three.js examples (`webgl_loader_md2`, `webgl_loader_md2_control`), stored in `public/models/md2/{ratamahatta,ogro}/` with several skins and separate MD2 weapon meshes. Two are skinned GLBs: the Hellhound (`models/zombie_dog_animation.glb`) and the Gold Dragon (`models/dragon_gold.glb`).

- **`MonsterTypes.js`** holds pure data: `MONSTER_TYPES` (walker, runner, listener, gunner, brute, hound, dragon, boss), with model, skins, weapons, height, HP, speed, melee, `sight` {range, fov}, `hearing` multiplier, `hunter`, `ranged`, `bigBody`, and pool size. GLB types instead name a `GLB_MODELS` entry (url + a map from the AI's clip names to the file's clips) and give a sphere `hitbox` (`[r, y, z, isHead]`), `bodyY`, `sepRadius` and `runRef`/`walkRef`. Creature fields: `scent` (smells players through walls and darkness), `pack` (one spots you, the rest nearby come), `pounce` (leaping bite), `flying` {altitude, dive}, `muzzle`, `healthBar`, `bossBar`. It also defines `ENEMY_GUNS` (hitscan machinegun/shotgun, bolt blaster/plasma, dragon `firebreath` with `trail` + `ignite`) and `getLevel(n)` (8 hand-made levels, then scaling; `dragon`/`dragonAt` work like `boss`/`bossAt`).
- **`MonsterPool.js` (`MonsterPools`)** loads every body, skin and weapon once and prewarms one pool per type. Each MD2 instance has body mesh + mixer, an optional weapon mesh + mixer playing the same clip names (as `MD2Character` does), a capsule body, a "?"/"!" marker sprite, and per-skin `mats` {base, hit, burn}. GLB models are normalised once (`_prepareGlb`: posed on frame 0 of `stand`, turned so head-minus-pelvis faces +Z, feet on y = 0, scaled to `height`) and cloned per instance with `SkeletonUtils`. Their compound sphere body turns with the monster (`orient(m)`). Flyers collide only with players and grenades. A GLB that fails to load just removes that type. `acquire(type, …)` / `release(m)`, with no scene add/remove.
- **`ZombieManager`** (targets come from `getTargets()`; see Co-op) runs a state machine per monster: wander → investigate ("?") → alert ("!", point animation and growl) → chase → search (last known position) → wander.
  - Sight: range × player visibility, FOV cone, and a line-of-sight raycast on `GROUP_WORLD` (glass doesn't block it). It builds an awareness meter and is throttled to `SENSE_INTERVAL`.
  - Hearing: `noise(x, z, radius, kind)` for `"step" | "shot" | "explosion" | "door"`. Hunter types (Listeners) charge at noises; others investigate them.
  - Ranged types hold a distance band, strafe, and fire in phases: cool → aim (red laser via `EnemyFire.laser`) → burst. Their aim lags the target.
  - Melee uses the attacker ring. Big bodies can't enter houses (`navigate(..., big)`).
  - Hellhounds: scent (`_smell`, scaled by `scentMul`, which rain lowers) builds awareness and keeps a chase alive without line of sight. `_spot` calls the pack within 34 m. `_tryPounce` / `_updatePounce` leap at 2.6–7.5 m and bite once on contact.
  - Dragon: flies (`flyY`; `_updateFlight` banks into turns and drops from `altitude` to `dive` while aiming), skips ground pathing, orbits wide in the ranged band and breathes fireballs from `muzzle`. Roofs block its sight and its fire.
  - Models without death clips die procedurally (`_proceduralDeath`): flinch, freeze, flyers fall and crash (`onCrash`), then keel over. `isHeadshot(m, point)` uses the head sphere for GLB types.
  - Hooks: `onKill`, `onSpotted`, `onDoorBang`, `onCrash`, `navigate`, `canSpawnAt`.
- **`LevelDirector.js`** runs intro → fight → cleared (intermission) → next level. It handles opening wave, spawn pacing, type mix from availability, mid-level entrances (`SPECIALS`: the Warlord at `bossAt`, dragons at `dragonAt`), re-centring wanderer homes on the player, and recycling wanderers past 115 m. Kills are counted per `levelId`. The first level starts on first pointer lock, and death restarts the level.
- **`src/combat/EnemyFire.js`** holds pooled bolts (dodgeable, wall-checked, optional splash), hitscan rays on `GROUP_WORLD | GROUP_PLAYER` with coloured tracers, and aiming lasers (`beginFrame` / `laser` / `endFrame`).
- **`src/ui/HealthBars.js`** draws every overhead monster health bar as one instanced, billboarded quad (one draw call). Hounds and dragons always show theirs; others once hurt.
- **`src/ui/GameHUD.js`** draws the level bar, banners, boss bar (Warlord or dragon, tinted by type colour), damage-direction arcs (`dealDamageToPlayer(..., srcX, srcZ)`), the noise meter, the clock/weather/flashlight widget under the minimap, the kill feed, film grain and the vignette (deeper at night). Fonts come from Google Fonts with system fallbacks: Teko (HUD), Creepster (titles), Special Elite (flavour text). In `main.js`, `updatePlayerNoise()` emits footsteps (sprint 17 m, jog 8 m, sneak/aim 3.5 m) and `playerVisibility()` (sprint ×1.25, still ×0.85, dark house ×0.45).

### World mood (`src/world/`)

- **The sky is fixed at a clear, sunny midday**: `main.js` creates `Environment` at 12:00 with `env.paused = true` and `Weather` in `"clear"` with `locked = true` (no rain, no night; `applyWorldClock` is a no-op and the lil-gui Time & Weather folder is gone). The code below still supports the cycle.
- **`Environment.js`**: day / evening / night cycle starting in the morning; `SEGMENTS` sets real minutes per stretch (≈ 8 min day, 1.5 dusk, 3 night, 1 dawn). A palette keyframed by hour drives the shader sky dome (gradient, sun, moon, twinkling stars, fbm clouds, lightning flashes), the sun/moon `DirectionalLight` (it dims to nothing at the horizon so the swap never pops), hemisphere + ambient light, fog colour/range and exposure. A third of nights get a blood moon. Exposes `darkness` (0..1), `lightDir` (shadow placement), `timeLabel`, `phase` and `onNightfall`.
- **`Weather.js`**: a clear → overcast → drizzle → rain → storm state machine. GPU rain streaks (9k instances wrapped around the camera, hidden indoors), ground splash rings, and storm lightning (sky flash, a bolt ribbon, delayed `onThunder`). Exposes `rain`, `cloud`, `wind` and `flash`.
- **`Atmosphere.js`**: drifting ground-mist billboards, smoke + flame plumes from burning wrecks (`setSources`), and one flickering firelight moved to the nearest wreck. All particle motion is in the vertex shader.
- **`Forest.js`** (`plantDeadForest`): procedurally grown leafless trees, one `InstancedMesh` per variant, each with a trunk collider. Tree sizes everywhere (`TREE_*_HEIGHT_MUL` and `DEAD_TREE_HEIGHT_MUL` in `main.js`) are multiples of `CHARACTER_HEIGHT`.
- In `main.js`, `updateMood()` ties it together: the flashlight (N; it comes on at dusk until you toggle it), wet ground (roughness/colour), ambience sound (rain, wind, night drone, stingers) and a heartbeat when hurt. Gameplay links: `playerVisibility()` drops at night unless the flashlight is on, and in rain; rain also shrinks footstep noise and hound scent. `window.env` / `window.weather` expose it. The "Monsters & Levels" folder can spawn a hound pack or a dragon.

### Co-op multiplayer (`server/`, `src/net/`)

- **`server/relay.mjs`** is a dumb WebSocket relay: rooms (max 8 for co-op, 100 for `br-` rooms), names and colours, host election (the longest-connected player takes over if the host leaves), and forwarding (`to: id | "host"`, or everyone else). It's attached to the Vite dev/preview server at `/ws` by the plugin in `vite.config.js`, so the game and the relay share one origin. It can also run standalone.
- **`Net`** is the client (`on(type, fn)`, `send(msg)`, `isHost` / `isClient`). **`Lobby`** handles name and room entry (`?room=` prefills it and preselects co-op) and the mode: solo, co-op, or battle royale. You pick a mode card, then press Play; the last mode is remembered (`babylon-fps:mode`). Its styles live in `src/net/lobby.css` (responsive: desktop, sideways phones, portrait), and the selected mode's colour (`--mode`) tints the screen.
- **Authority:** the host runs `ZombieManager` + `LevelDirector` and streams `mon` snapshots (`MonsterSync`, 12 Hz: 12 numbers per monster) plus `lvl` (2 Hz) and `lev` events. Clients turn their pools into kinematic puppets (`pool.setPuppetMode(true)`), never run AI, and send `hit` / `noise` to the host. Every player streams `st` (20 Hz). `RemotePlayers` renders teammates (Soldier + name-tag sprite + kinematic capsule whose `body.playerTarget` makes them targetable).
- **Targets:** `ZombieManager` / `EnemyFire` take `getTargets()` (local + remote players) and report hits through `onPlayerHit(target, …)`, which sends `hurt` to a remote target. Monsters pick the seen/nearest player and switch to a much closer visible one.
- GLB creatures sync like the rest: a flyer's altitude rides in the snapshot's root y, `MonsterSync.ANIMS` gained `walk` (appended, because indices are on the wire), and clients play the procedural deaths locally.
- **Shared events:** `shot` (teammate tracers and sound), `throw` (every client simulates it; only the host's copy damages monsters, each client damages its own player), `door` / `light` / `world` (state for late joiners), `drop` (host-rolled loot), `kill` (credit to `lastHitBy`), `ef` (host's monster gunfire replayed as `visualOnly`), `wipe`.
- **Horde scaling:** `LevelDirector.playerCount` multiplies totals (+65% per extra player), max alive (+55%, cap 40) and Warlords (+1 at 3+ players). In co-op, death respawns you next to a teammate; the level restarts only when the whole squad is down for 4 s.

### Battle royale (`src/br/`)

The lobby offers three modes: Solo, Co-op vs Zombies, and Battle Royale. `gameMode` in `main.js` is `"solo" | "coop" | "br"`; `isBR()` gates every difference. Battle royale rooms are `br-<code>` on the same relay (no relay changes), so they never mix with co-op rooms.

- **`BattleRoyale.js`** is pure rules: plane route (`planeRoute` / `planeAt`), zone circles and phases (`ZONE_PHASES`, `zoneCircles`, `zoneAt`), loot layout (`lootPlan`, `BR_FIELD_LOOT`, `BR_HOUSE_LOOT`), and PvP damage (`PVP_DAMAGE`, `PVP_HEADSHOT`). Everything derives from the match seed, so one `brstart { seed, ids }` builds the same match on every client.
- **`BrVisuals.js`**: the blue zone wall (open cylinder, scrolling shader), the drop plane, parachutes, and `setSkydivePose`. **`BrHud.js`**: alive/kills/zone bar, outside-zone overlay, hints, spectator bar and result screens. The big map is the shared `WorldMap` (zone, next circle, plane route via `_mapState`).
- **Flow** (host-driven): warm-up (warm-up kit, PvP on, respawn after 3 s) → countdown (auto 25 s once 2+ players are in; the host can press Enter, alone that's a practice drop) → match → results (12 s) → `brwarm`. The host streams `br` at 2 Hz (state, seed, match clock, alive ids, hour, weather); late joiners rebuild the match from it and spectate as a hidden "ghost".
- **Drop**: `br.flight` is `PHASE_PLANE → PHASE_FALL → PHASE_CHUTE → PHASE_GROUND` (constants in `RemotePlayers.js`, sent as `ph` in `st`). `brUpdateFlight` replaces the ground controller while airborne; the chute opens on Space or by itself at `FREEFALL.chuteHeight`. You start empty-handed (`inventory.reset(true)`, `inventory.current === null`).
- **PvP**: hitscan adds `GROUP_PLAYER` to the mask (your own capsule is masked out for the ray). The shooter sends one `pvp` per victim per shot; the victim applies it (each player owns their health), remembers the attacker, and on death broadcasts `elim` and spills their loot as shared pickups. Grenades and molotovs credit their owner. The host ends the match when one player is left (or none, in a practice drop).
- **Island scale**: `ZONE_START_RADIUS` 470 with an extra opening phase (to 260 m); the plane route `halfLength` is 500 and `ejectRadius` 360.
- **Loot is mostly indoors**: `lootPlan` fills 88% of house / shed / city shop and rooftop / building site / town building / cave spots from `BR_HOUSE_LOOT`. `BR_FIELD_LOOT` (open ground, `isOpenGround`, which also rejects water, fields and the beach) is a small top-up.
- **Shared loot**: pickups take an optional network id; `take { i }` removes one for everyone, `drop` carries `i`, `a` ([ammo, reserve]) and `c` (throwable count).
- **Red zones** (`noteShot` / `fightZones` in `main.js`, match only): two or more different players firing within `FIGHT_RADIUS` of each other inside `FIGHT_WINDOW` s start a red zone, drawn on the minimap (rim dot when off-range) and the big map, with a `#redzone-alert` message ("Players fighting 120 m NE"). It fades `FIGHT_LIFE` s after its last shot. Other players' name tags and health bars are hidden in battle royale.
- **Bots** (`src/br/Bots.js`, `bots` in `main.js`): seven AI players (`BOT_COUNT`, ids `bot:N`, `isBotId()`) join every battle royale room on the host (`bots.spawnAll()` in `enterBattleRoyale`), so the warm-up countdown runs even alone. The host simulates them and feeds each one into `remotePlayers.applyState()` (same soldier, capsule, animations, kill feed, spectating); others get one `bots` packet at 10 Hz (`bots.netTick` / `applyNet`). Per bot: skill, drop from the plane toward loot near the route (`onMatch`: jump time, freefall, chute), looting by what it wants (`_worth`: better guns, armour, ammo, heals, throwables; taken through the host's shared-loot path), zone margin, sight (range, FOV, `GROUP_WORLD` ray, smoke), reaction time and aim error that settles while tracking, bursts / reloads / strafing / crouching in its gun's range band, grenades where you were and molotovs at someone holding still, healing when quiet, doors (`openDoorAt` when pathing hits a closed one), a free vehicle when the zone is far (`Vehicle.drive` with AI input, `veh` in its packet), and unsticking (skips loot it can't reach, backs out along the freest line). Movement uses the monsters' `navigate` plus a wall probe ray; height from `surfaceAt`. Bot messages carry `b` (shot, throw, anim, pvp from a bot); a hit on a bot goes to the host as `pvp { v }` (`sendPvp`), which owns bot health (`bots.damage`, armour like a player's); grenades and molotovs hurt bots on the host (`blast` / `burn`); a dead bot spills its kit (`spillLoot`) and sends `elim`. A new host `adopt()`s the bots.
- **Spectating**: eliminated players follow living ones (`updateSpectatorCamera`, A/D or click to switch). `focusPos` (you, or whoever you watch) drives the minimap, shadows, ground chunks and pickup culling.
- Day/night and weather keep running; co-op and battle royale clients follow the host's clock and weather (`applyWorldClock`, `weather.locked`).

### Touch controls & Android app (`src/input/`, `android/`)

- **`TouchControls.js`** turns on for phones/tablets and the Capacitor app (`IS_TOUCH`; `?touch=1` forces it on desktop) and adds `body.touch`. It never changes game state itself: `main.js` reads `moveX` / `moveY` / `sprint` (analog joystick; drag past the ring to lock sprint) and gets everything else through callbacks, mostly `key(code, pressed)` → `setKey()`, so every button behaves exactly like its key. Drag on the right (and on the fire / throw buttons) calls `lookBy()`, the same function the mouse uses; the gyroscope (`devicemotion` rotationRate, mapped by screen angle) calls `turnBy()` in radians. Hotbar slots (`data-hb`) and the context prompt rows are tappable. Settings (look speed, gyro mode/sensitivity, invert, button size/opacity) live in localStorage.
- **Locking:** touch has no pointer lock, so `isLocked()` is `touchPlaying || pointerLockElement === canvas`. Always go through `requestLock()` / `releaseLock()` / `onLockChange()`, never `exitPointerLock()` directly. `updateTouch()` feeds the overlay a context object each frame; it only touches the DOM when that changes.
- **`touch.css`** re-lays the HUD around the thumbs with CSS `zoom`. `zoom` scales an element's offsets too, so offsets there are written as screen px ÷ zoom. style.css has `* { overflow: hidden }`; the touch layer opts out.
- **Android:** Capacitor 8 (`capacitor.config.json`, `webDir: dist`). `MainActivity` keeps the screen on, hides the system bars and forwards the back button as a `androidback` window event. The app runs at `https://localhost`, so the relay URL must be baked in (`.env.android`) and the relay's `ALLOWED_ORIGINS` (if set) must include `https://localhost`.

### Deployment

See `DEPLOY.md`. The game goes on Vercel (`vercel.json`) and the relay on Render (`render.yaml`, `server/package.json`), because Vercel can't hold WebSockets. `RELAY_URL` or `VITE_RELAY_URL` (build-time, exposed via `envPrefix`) points the client at the relay; unset, it uses the dev server's `/ws`. The relay's `ALLOWED_ORIGINS` limits which sites may connect. Only optimized runtime assets are committed (see `.gitignore` / `.vercelignore`), about 8 MB. `Soldier.js` and `loadGLB()` load `*.opt.glb` first.

### Physics (`cannon-es`)

Four named `CANNON.Material` instances: `ground`, `character`, `static`, `monster`. Contact materials between them are registered at startup in `main.js`. All static world objects (houses, trees) use mass-0 bodies with the `static` material. Player uses a capsule compound body (two spheres + cylinder). Zombies also use capsule bodies but with zero friction on ground contact so steering remains direct.

### Ground & landscape (`src/world/Terrain.js`, `Backdrop.js`, `Grass.js`, `Rocks.js`)

- **Terrain**: one seeded heightmap (`TERRAIN_STEP` 2.5 m over ±`TERRAIN_HALF` 520 m) of rolling hills (higher ground past ~260 m), flattened (`pads`) under houses, props, spawn and the rickshaw's parking spot. The map is an island about 1 km across: past `shoreRadius(x, z)` (`SHORE_R` 470 m ± a wobble, two bays) the ground slopes into the sea (`SEA_Y`). `seaDepth()` only counts within `SEA_INLAND` of the waterline, because the cave floors inland lie below sea level too. `keepInBounds()` walks you back once the sea is deeper than 1.1 m; `PLAY_RADIUS` (510 m) is still the hard edge. The render mesh is split into `RENDER_TILE` (100 m) tiles, with normals from the height gradient so the seams match, and they go into `WorldChunks`.
- **WorldChunks** (`src/world/Chunks.js`): distance culling for static meshes. `chunks.add(obj, x, z, r)` / `addMesh(mesh)`; `update()` (5×/s, round the camera) hides whatever is past `RANGE` (245 m). It covers terrain tiles, city and plot cells, boats, and every `InstancedMesh` flagged `userData.chunk` (rocks, dead trees, power poles), which `splitInstanced()` cuts into 120 m cells at the end of `loadWorld()`. Colliders are untouched, so it's render-only and the same for every player. Built in `loadWorld()` after the houses are placed, since it flattens itself under them. It feeds three things: cannon `Heightfield` tiles (`TILE_CELLS` cells each, so long rays stay cheap; they collide only with the player and projectiles), one render mesh (vertex-tinted by slope and height, shares `planeMaterial`), and a half-float texture (R = height, G = grass density) for GPU effects via `TERRAIN_GLSL` / `terrainUniforms`.
- **`groundHeight(x, z)`** is the CPU lookup everything uses instead of y = 0: monsters (`_pinToGround`, spawns, `MonsterSync`, which sends height *above* the ground), pickups, fires and scorch marks, trees, debris, spawns and BR landing. Never assume flat ground.
- **Water** (`src/world/Water.js`): one opaque `waterMaterial()` (a patched `MeshStandardMaterial`) for the sea, the river and the ponds. It colours itself by real depth from the terrain texture (silty above sea level, clear teal below), with a foam band where it meets the ground. There's no transparency. The sea is a ring whose inner edge follows the coast (`buildSea`).
- **Bare ground**: `planeMaterial`'s grass texture loses its green wherever the terrain's vertex colour leans brown (red over green). So `tint` hooks (field soil, river mud, road shoulders, beach sand `beachTint`) read as earth.
- **Backdrop**: the distant mountain ring (now a far coast rising out of the sea at `INNER` 640 m), a sea-coloured floor and the sky dome live in their own scene, drawn first with a far camera; then the depth is cleared and the game scene is drawn with its 220 m far plane (`renderFrame()`, `renderer.autoClear = false`). The mountains are lit by uniforms copied from the day/night lights and hazed into the fog colour.
- **Grass**: instanced tufts wrapped around the camera entirely on the GPU (like the rain), placed with the height texture, thinned by the density channel (none in houses or under props), swaying with `weather.wind`. It's trampled flat round the nearest `GRASS_FLATTENERS` monsters and players (`updateGrassTrample()`), so low monsters like hounds can't hide in it.
- **Rocks**: instanced lumpy stones. Boulders (`BOULDER_COUNT`) have sphere colliders and `mapObstacles` entries and must stay identical on every quality preset; pebbles are decoration and scale with quality. Cover rocks (`COVER_ROCK_COUNT`, own `coverRng`) are 2–3.6 m tall, stretched stones to hide behind, each with an upright `Cylinder` collider (stops bullets); identical on every preset too.
- **College gate** (`src/world/CollegeGate.js`, `public/models/msbecl_gate_final.opt.glb`): the MSBECL gate across the North Road (`COLLEGE_GATE`), modelled to scale (spans its local X, two lanes either side of a guard booth). Colliders are the cubes of the model's own `College_Gate_Collision` mesh (split by index connectivity, so the booth stays hollow); the ones on the ground go into `mapObstacles` / `navObstacles`. The four iron leaves and the booth door play the model's `*_Open` / `*_Close` clips: the gates start open, **F** next to a lane swings both (`useGate`, net `gate { p, o }`, `world.gate` for late joiners), and a shut gate adds a `GROUP_GLASS` panel per lane (bullets pass the bars) plus lane obstacles for vehicles and pathing. The leaf material is cut out (`alphaTest`) instead of blended. Towns, trees, rocks and poles keep clear (`blocks()`).

### Shivpur, the city (`src/world/City.js`)

- `CITY` in Towns.js: a street grid (Station / Market / Gandhi / Nehru Road, the Highway and the Outer Ring) round (342, −50), on its own plateau. `City` lines every street with buildings 8–13 m wide, sometimes with alleys between them. Footprints are tested against all roads and each other (`obbOverlap`).
- **A building**: the ground floor is an open shop (shutter, signboard from the `SIGNS` atlas, shelves, counter, loot). It's walk-in, and `inside()` counts as indoors for rain and `playerVisibility()`. Above it sit 1–4 solid storeys (not enterable) with a canvas facade texture (grilled window + sunshade per `BAY` × `FH`) and optional front balconies. The flat roof has a parapet and a water tank. Half the buildings have a two-lane switchback stair up the back (ramp colliders in a body monsters don't collide with), leading to roof loot and a gap in the parapet.
- Geometry is merged per 60 m cell and material (facade / plain / sign) and registered with `WorldChunks`. There's one static body per building plus one for its stairs, and the footprint (with stairs) goes into `mapObstacles` (`city: true`). `lootSpots` join the BR and solo loot. Towns, fields, plots, trees, grass and spawns keep out (`inCityBox`, `inArea`, `blocks`).

### Plots & building sites (`src/world/Plots.js`)

- Seeded walled plots along every road (`SETBACK` from the shoulder, gate gap toward the road). There are three kinds: `empty` (brick or plastered wall, sand heap, brick pile, some overgrown), `unfinished` (panels missing or stepped low, low ones jumpable), and `construction` (an RCC frame with rebar, a slab at `FRAME_H` reached by a plank ramp, cement bags, loot under and on the slab).
- Each wall panel is a box collider and a `mapObstacles` entry (`plot: true`); the whole plot is one `navObstacles` box. Meshes are merged per cell (brick texture / plain) and go into `WorldChunks`. `grass()` / `tint()` feed buildTerrain.

### River, ponds & farmland (`src/world/River.js`, `src/world/Farmland.js`)

- **River**: `RIVER` (the Sona River) is a fixed centreline from the lake east of Crossroads, under the Highway, the Ring Road and the Outer Ring, out into the south-east bay. Through high ground its banks widen into a valley (`VALLEY`). `PONDS` holds the lake and two village ponds. `setProfile()` gives it a water level that only ever falls downstream (to `SEA_Y` at the mouth). In buildTerrain, `modify` carves a parabolic bed with a levee each side, and `tint` muds the banks. The water is one ribbon + discs mesh. `wet(x, z, pad)` keeps towns, trees, rocks, poles, fields and loot off the water; `depthAt()` / `waterDepthAt()` in `main.js` slow wading players and fording vehicles.
- **Bridges**: where a road crosses (`findCrossings`), `roads.setProfile` gets a hump (`bridgeLift`) and `Roads.modify` fills the channel, which makes a causeway. `buildBridges()` adds parapets (colliders + `mapObstacles`) and concrete side walls with culvert mouths. Order in buildTerrain: `caveTerrain(roads.modify(river.modify(h)))`.
- **Farmland**: `layoutFields()` (seeded, before the terrain) picks rectangular plots in open country, squared to the nearest road. Each holds sugarcane (in belts), wheat, veg, stubble (with haystacks) or ploughed furrows. Crops are decoration: one shuffled, swaying `InstancedMesh` per field, thinned with distance (`FULL_DIST` to `DRAW_DIST`, down to `FAR_SHARE`); clump density follows the quality preset. Sugarcane lanes are part of the layout. `inCane()` cuts `playerVisibility()` and hides you from battle royale bots (`concealed`). Some fields get a farm shed (a `cabin` house, so its loot spots join the house loot). Fields keep grass (`grass()`), trees, rocks and open-ground loot out.
- **Potholes**: `roads.buildPotholes()` adds instanced decals (potholes and patched squares, none at bridges or junctions). They're thicker out in the country and have no colliders.

### Caves (`src/world/Caves.js`)

Two underground networks (`NETWORKS`: Hollow Ridge, Bone Hollow), each a rock massif (a craggy hill) with tunnels and chambers running under it and 4 mouths in its flanks. Layouts are fixed node graphs: `m` mouth, `j` junction, `c` chamber (radius); edges carry a width multiplier.

- **Why a massif:** the terrain heightfield can't hold a tunnel (one height per x, z; cannon treats everything below it as solid). Instead `caveTerrain()` (buildTerrain's `modify`) sinks the ground to the cave floor under every tunnel and chamber, so **the floor is the terrain** and every `groundHeight()` user works underground. The floor sits `FLOOR_DEPTH` below the lowest ground round the network; mouth tunnels ramp from the outside ground down to it.
- **Rock:** one SDF per massif, solid = below the hill skin (`skinHeight`: dome over the tunnel spine + rugged noise, 3D crag noise) and outside the void (`voidDist`: squashed capsules per tunnel with varying width and noisy walls, ellipsoid chambers, smooth-min joins, flat floor clip), joined with a smooth max so mouths get a rounded rim. Chambers keep a minimum roof. Polygonised with surface nets on a `CELL` grid into one flat-shaded mesh (outer slopes, walls, ceilings, mouths), chunked by `CHUNK` for frustum culling.
- **Build:** `precomputeCaves()` (field, mesh, colours, AO, torches, baked light; no terrain needed) runs in `loadWorld()` while the models download; `new Caves()` (after the terrain) drops triangles under the ground, chunks, and makes the colliders. About 0.5 s + 0.25 s on a desktop.
- **Collision:** chunked `Trimesh` bodies in `GROUP_WORLD` (cannon's Trimesh keeps indices in an Int16Array: keep each chunk under 32k vertices; `RockTrimesh` skips cannon's slow, unused edge list). Only spheres collide with trimeshes in cannon-es (the capsule's spheres, grenades, monster hit spheres), and every raycast (bullets, camera boom, ground ray, monster sight, blast shielding) stops at rock. Floor triangles are left out (the terrain is the floor). `keepOnCaveFloor()` stops the frictionless capsule riding up the curved tunnel walls unless you jumped.
- **Light:** the rock shader (`rockMaterial`) scales sun/sky/ambient by a per-vertex `aSky` (1 outside, 0 more than ~12 m past a mouth) and adds baked torchlight (`aTorch`, occlusion-tested through the field). `QUALITY.caveLights` real point lights follow the torches nearest the camera and flicker. Torches (`placeTorches`: inside each mouth, at junctions, round chambers, in some long tunnels; the rest stays dark) are one merged mesh, one draw call of GPU flame quads and one of embers. Underground (`caveDepth`, from `caves.depthAt` at the camera) `dimUnderground()` takes the sun, sky and ambient light and the fog down, rain is hidden (`indoor`), wind/rain sounds fade, water drips and torches crackle (`Sfx.drip`, `Sfx.crackle`), PostFX gets darker edges, and `playerVisibility()` drops away from torches unless the flashlight is on. Ground mist skips anywhere the terrain's grass density is 0 (caves, houses, props).
- **Monsters:** `caves.navigate()` runs before `houses.navigate()`: an all-pairs shortest-path graph over the tunnel nodes, mouths and an approach point outside each mouth, used when the monster or its target is in a tunnel (points in the rock beside a tunnel snap to it); outside, a ring of waypoints round each hill when a straight path would hit rock (`_blocked`). Big bodies wait outside the nearest mouth. No spawns on or near a massif (`caveBlocks`); flyers keep altitude over the hills (`zombieManager.flyFloor`).
- **World:** houses, trees, stones, the dead forest and spawns keep off the massifs (`caveBlocks`), the grass mask is 0 there (`caveGrass`), the rickshaw can drive in through a mouth but not into rock (`caves.solidAt`), chambers and junctions hold loot (`caves.lootSpots`, solo/co-op world loot and the BR loot plan), the world map shows the hills in its relief (`mapHeight`) plus dashed tunnels, mouths and names, and the BR chute height measures to the hill top (`surfaceHeight`). The BR zone applies underground as anywhere else. Everything is deterministic and identical on every quality preset (only the number of torch lights differs).

### Vehicles: auto-rickshaws, Thars and tractors (`src/vehicles/Vehicle.js`, `DustFX.js`)

- `VEHICLES` holds each kind's handling and layout (speed, steering, fuel, seat, lamps, wheels, collider, `modelYaw`, engine `tone`); `Vehicle` is one drivable instance. `VEHICLE_SPAWNS` in `main.js` parks 9 of them (rickshaws and Thars) by the spawn and on road shoulders in the towns (`vehicleSpawns()`, `PARK_OFFSET` inside the power-pole line); the list index is the network id (so new spawns are appended: five tractors at the farmsteads follow the original nine). The Thar falls back to `standInJeep()` and the rickshaw to the old free model when the India models are missing. The tractor is always the procedural `standInTractor()`, with wheels the vehicle builds and spins itself (`spec.spin`; front ones steer).
- **Grip & drift**: `drive()` takes `input.grip` from `surfaceAt()` in `main.js` (asphalt 1, dirt/fields ~0.6–0.75, sand, water). When a turn needs more sideways force than `spec.grip × grip × g`, the excess pushes the vehicle outward as `slip`, which the tyres scrub off; the handbrake halves the grip. `skid` = |slip| leans the body (roll). The tractor (`grip` 0.72, `slide` 0.2, slow `steerRate`) slides most.
- **Dust**: `emitDust()` puts puffs behind the rear wheels into `DustFX` (one ring-buffered instanced billboard mesh, life computed in the vertex shader). The rate grows with speed × `spec.dust` × surface and with the skid. Puffs are coloured by surface (`DUST`); on asphalt only a slide makes tyre smoke. Every driven vehicle within 90 m emits, remote ones too (speed only).
- Arcade driving (bicycle-model steering, no wheel physics). It follows the terrain by sampling `groundHeight` under its wheels, and `solidAt(x, z, r, self)` in `main.js` stops it against `mapObstacles` (houses, trees, boulders, map edge) and other vehicles. A kinematic box in `GROUP_VEHICLE` shoves players and monsters; bullets, the camera and loot checks ignore it (the driver can be shot). Parked vehicles aren't re-posed every frame.
- **V** gets in/out of the nearest (`toggleVehicle` / `nearestVehicle`), W/S throttle/brake-reverse, A/D steer, Space handbrake. While driving (`drive.car`), the player body is pinned to the seat (`vehicleAfterStep`), `collisionResponse` is off, weapons are disabled, `Soldier.seated` bends the legs, and the camera blends to the `drive` rig. Driving into monsters (or players, in the BR) damages them (`vehicleRunOver`, `spec.runOver`).
- **Petrol**: driving burns fuel (`spec.burn`, `idleBurn`); an empty tank won't move. Petrol cans add `spec.canFuel` with **T** next to it or while driving.
- **Headlights**: lamps and tail lights glow per vehicle; the beam is one shared SpotLight (`headlight`) lent to the closest lit vehicle (`aimHeadlight`): every light in the scene costs every pixel. One engine voice (`sfx.setRickshaw(…, tone)`) follows yours or the nearest someone drives.
- **Sync**: the driver adds `veh: [x, z, yaw, speed, fuel, index]` to `st`; others `setRemote` and smooth. `vfuel { f, i }` shares refuels; `world.veh` carries every parked pose for late joiners. If two players get in at once the lower id keeps it. The BR parks them all back every round (`resetVehicles`).

### Post-processing & kill streaks (`src/render/PostFX.js`, `src/ui/KillStreak.js`)

- **`PostFX`** (after three's `webgl_postprocessing_advanced`): the scene renders into one HalfFloat target (`postFx.begin()` / `end()` around `renderFrame()`; MSAA moves there from the canvas), `UnrealBloomPass` adds onto it (`QUALITY.post === "full"`), and one `RawShaderMaterial` pass does ACES + sRGB, chromatic aberration, saturation/contrast, bleach bypass, tint, vignette, flashes and film grain/scanlines. `QUALITY.post` is `"off"` (direct to screen, as before) / `"grade"` / `"full"`. `warmUpGpu()` compiles with the post target bound, since tone mapping and colour space are part of every program. Resize and dynamic resolution call `syncPostSize()`.
- The grade follows the game (`updatePostFx()` in `main.js`): night bleaches and cools it, blood moon reddens, low health drains colour and throbs red with a heartbeat, slow motion goes cold with scanlines, frenzy goes hot with extra bloom, death goes grey. Battle royale adds its own moments: outside the blue zone it goes cold and pulses (`zone`, stronger the deeper you are), freefall fringes and narrows (`freefall`), a win flashes gold and being eliminated flashes red. Custom shaders must never produce NaN (e.g. `pow()` of a negative): one NaN pixel is smeared over the whole screen by the bloom and turns it black (the zone wall clamps its uv for this). `postFx.kick(strength, color)` flashes (kills, streak tiers, level cleared) and `postFx.hurt(x)` pulses red edges.
- **`KillStreak`**: kills within 4.5 s build a streak (`onLocalKill(headshot)` is called from every kill-credit path: solo/host, co-op `kill`, BR `elim`). Tiers (DOUBLE KILL … GODLIKE) get a callout and heal (not in the BR); RAMPAGE and up start a frenzy (kills heal +3, each kill extends it). The best streak is saved in localStorage (`babylon-fps:bestStreak`).
- **`Confetti`** (`src/ui/Confetti.js`, after React Bits Pro's Celebration Cursor): tumbling paper on one 2D canvas with its own rAF loop that runs only while pieces live (pooled, `MAX_PIECES`). `celebrate("level" | "victory")` fires corner cannons and bursts on a cleared level and a battle royale win; while it runs and the mouse is free, moving spills a trail and clicking bursts.
- **Aqua blood**: blood is aqua, not red. `Effects.impact(..., "blood")` sprays round drops (Points with a soft sprite), a fine mist and a dripping wound (`drip`); drops land on `effects.groundAt` (the terrain, plus the asphalt's lift on roads) and leave stains (`splats`, one InstancedMesh, shrinking away after `SPLAT_LIFE`). `effects.bleed(pos, awayX, awayZ, n)` sprays away from the attacker. `dealDamageToPlayer` bleeds you and calls `ScreenBlood.hit(strength, angle)` (`src/ui/ScreenBlood.js`: glossy beads on a 2D canvas over the game, mostly on the side the hit came from, running down and fading; own rAF loop only while drops live); hits within `CLOSE_SPLASH` spatter the screen a little; a teammate hit by a monster bleeds where everyone can see it.
- **Pause**: Esc (or anything that drops the pointer lock, including the Tab inventory) freezes a solo game: `gamePaused()` makes `animate()` pass `delta = 0` and the audio is suspended. Co-op and the BR can't pause (`canPause()`); the pause screen says so. After the first click in, the start screen reads PAUSED / "Click to resume".
- **Bullet time** (solo only): `slowFor(seconds, scale)` dips `timeScale` (level cleared 1.6 s at 0.3, headshot kills a 0.12 s hitch), combined with the weapon wheel's slow motion in `updateWeaponWheel()`.

### XP & daily challenges (`src/meta/Progress.js`, `src/ui/ProgressUI.js`)

- **`Progress`** is pure state in localStorage (`babylon-fps:progress`): total XP (level cost `levelCost(l)`, rank titles `RANKS`), three daily challenges (easy / medium / hard, dealt from a seed of the local date so everyone gets the same ones, at most one battle-royale challenge, one reroll a day), a +150 XP bonus for finishing all three, and a day streak. Kill XP is per monster type (`KILL_XP`). Rebalance in `CHALLENGES` / `XP`.
- `main.js` only reports events: `progress.kill(type, killCause, night)` (solo/host `onKill`, and co-op `kill`, whose message now carries `c` = killCause), `pvpKill`, `streak` (from `onLocalKill`), `levelCleared`, `brFinished(place, players)` (practice drops don't count), `drive(metres)`. `runXp` resets with `killsThisLife` and shows on the death screen and BR results. The benchmark doesn't count.
- **`ProgressUI`**: the level / XP badge in the lobby's top bar (`#lobby-profile`), the daily challenges panel (`#lobby-progress`), the "+XP" ticker under the crosshair, and toasts for challenge progress, completion and level-ups. Event-driven, nothing per frame.

### Graphics quality (`src/quality.js`)

`QUALITY` is chosen once at startup: the lobby's Graphics picker (saved in localStorage; changing it reloads) or "auto", which detects the device (`navigator.deviceMemory`, cores, GPU name; software or 4 GB / 4-core machines get Low). Presets set antialiasing, pixel-ratio range for dynamic resolution, shadows (off / every other frame / every frame), grass, pebble, rain and mist counts, terrain render density, mountain detail and texture anisotropy. Only visual things may differ between presets: anything with a collider must be identical, or battle royale loot (placed by `isOpenGround`) would differ between players. Presets also set the point-light budget (`fireLights`, `houseLights`, `wreckLight`): every light costs every lit pixel even at intensity 0. On touch devices `TOUCH_TUNING` overrides each preset (MSAA and a higher pixel ratio, less grass/rain/mist, fewer lights) and auto-detect sorts phones by GPU family (`detectPhoneQuality`). Dynamic resolution only lowers the pixel ratio when the frame is GPU-bound: if game logic alone takes most of the frame (typical on phones), a lower resolution would just blur it.

### World assets

`loadWorld()` in `main.js` loads GLB/WRL models and registers them in `editableModels` via `createEditableModel()` (the vehicles, the college gate, stalls and Indian props are placed by their own modules instead). Each editable model gets a lil-gui folder for live position/rotation/scale tuning. The "Log Coordinates to Console" button prints JSON of all positions so they can be hardcoded.

Scatter positions use a seeded LCG RNG (`makeLCG(0xdeadbeef)`) so the world layout is deterministic across reloads.

### Stances (`src/player/Stance.js`)

**C** crouches, **Z** goes prone (each again, Space or sprinting stands you up; Space from prone goes to crouch). `STANCES` sets move speed, camera pivot height, how visible / loud you are, and the monsters' aim and eye offsets (`target.aimOff`, `target.eyeOff`). `setCapsuleStance` turns the capsule's cylinder off and drops its top sphere (rays skip shapes with `collisionResponse = false`), so lower stances are much harder to hit. Rising checks headroom (`roomToRise`). You can fire from every stance. Teammates get the stance through `st.sn`. `Soldier.stance`: crouch bends the legs and drops the hips; prone tips `soldier.model` onto its belly, leans the chest via the spine aim and swings the arms back up (`_raiseArms`). Touch has crouch / prone buttons under the fire button.

### Player (`src/player/Soldier.js` + `main.js`)

Over-the-shoulder camera with pointer lock: smoothed pivot follow, hip/aim/sprint rig presets blended by `aimBlend`/`sprintBlend`, boom collision via a cannon raycast against `GROUP_WORLD`, recoil + trauma shake. WASD is camera-relative; the body faces the aim direction (strafe mode). The controller owns `moveVelocity` and writes it to the body every frame, so player contacts are frictionless. Knockback is a separate decaying velocity added on top.

`Soldier` splits each clip into lower-body (legs/hips) and upper-body (Abdomen and children) actions.

Animation beyond walking and aiming: `playClip(key, dur, weight)` plays an upper-body one-shot from the model's own clips (`ONE_SHOTS`: Interact for doors, light switches and medkits; HitRecieve / HitRecieve_2 when hit, so `soldier.opt.glb` keeps those 11 clips) over the locomotion, and `playGesture(name, dur)` a procedural one in `_procedural()`: `reload` (gun tips over, left hand to the pouch and back), `eat` (Parle-G packet in the left hand to the mouth, chewing; `setHandProp`), `vault` / `climb` (arms up for the sill or wall top, knees tucked). `s.air` tucks the knees in a jump and `s.health` blends in a wounded posture (hunched, head down, a hand on the wound, a limp). `main.js` drives them through `playerAnim`, which also sends an `anim` message so teammates see them (`RemotePlayers` passes `health` from `st`). Legs blend Idle_Gun / Run / Run_Back / Run_Left / Run_Right by local velocity on a shared phase. The upper body cross-fades from locomotion to Idle_Gun_Pointing / Idle_Gun_Shoot when aiming or firing. A procedural spine twist (abdomen + chest) then points the gun along the camera yaw/pitch. The SMG is aligned to the right hand once at load, using the pointing pose.

### Combat (`src/combat/`)

- Hitscan from the camera through the crosshair (one ray per pellet) (`world.raycastClosest`, mask `GROUP_WORLD | GROUP_ZOMBIE`). Monster bodies carry `body.zombie` back-references. Hits in the top `HEAD_HEIGHT` (scaled by monster height) are headshots.
- `Effects` holds pooled tracers, one muzzle-flash sprite with a persistent point light (never added or removed, so no shader recompiles), and a single `Points` particle buffer.
- **Audio** (`src/combat/Sfx.js`): recorded CC0 samples in `public/sounds/` (≈1.2 MB, `<group>_<n>.ogg` + `manifest.json`, credits in `CREDITS.md`) built by `scripts/build-sounds.py <SRC>` from the downloaded packs (it cuts single shots / barks / wing beats out of long recordings, layers the grenade, makes the fire loop seamless, levels everything). `sfx.preload()` fetches them at boot; they decode on the first gesture, and every method falls back to its old synthesized sound until then. `play(group, { at, vol, rate, ref, rolloff, wet, low })` picks a random variant; `at` ({x, y, z}) routes it through a PannerNode (HRTF on desktop, equal-power on touch) with distance roll-off and air absorption, and `setListener()` follows the camera every frame (`updateAudio()` in `main.js`), so sounds come from their side. A shared convolver reverb (`setSpace`: outdoor / indoor / cave) and a waveshaper soft-clip limiter sit on the master (not a DynamicsCompressor: it flattens gunshot transients). Ambience, engines, the howl and UI blips stay synthesized.
- **`MonsterAudio`** (`src/audio/MonsterAudio.js`) voices every monster from replicated state (state → chase: alert call; animation: attack / pain / pounce; dying; distance walked: footsteps; flying: wing beats), so host and co-op clients hear the same thing. Per-type groups and pitch are in `VOICES`. Player footsteps: yours on the `updatePlayerNoise()` rhythm, remote players' from `RemotePlayers.onStep`; `footSurface()` picks wood (houses), stone (caves) or grass.
- Collision groups live in `src/physicsGroups.js`. Dying zombies switch to `GROUP_NONE`.
- `ZombieManager` handles hit flash, stagger and pain clips, death clips (the MD2 death/pain sequences are split into `death1..3` / `pain1..3`), corpse sinking then pool release, gunfire `alert()`, and a spawner that keeps `maxAlive` zombies around the player.

### Weapons, items & inventory

- **`src/combat/weapons.js`** holds pure data: `WEAPONS` (pistol, smg, shotgun, rifle, sniper; per-gun fire rate, mag, reserve, spread, recoil, pellets, aim FOV, sound profile), `THROWABLES`, `MEDKIT`, `GRENADE` / `MOLOTOV` tuning, and `PICKUP_KINDS`. Rebalance here.
- **`src/items/ItemModels.js`** builds low-poly procedural models (all guns except the held SMG GLB, plus grenade, molotov, ammo crate, medkit) with shared geometry/materials. Gun frame: origin is the grip, +X is the barrel, `userData.muzzle` is the barrel tip. `renderItemIcon()` renders white silhouettes for HUD icons once at boot.
- **`Inventory`** (`src/inventory/`) is pure state: one of each gun with its own `ammo` / `reserve` / `att` ({ optic, muzzle, mag, grip }), stacks (throwables, medkits, petrol, loose attachments in `bag`), and worn `gear` ({ helmet, vest, backpack }: { id, dur }). Carrying is limited per kind (`maxOf`) and by weight: `load` vs `capacity` (`BASE_CAPACITY` + backpack + vest). `magSize(id)` includes the extended mag. Every change bumps `version`. **`InventoryUI`** builds the hotbar, pickup prompt, pickup feed and the gear chips under the health card (`#gear-hud`), and touches the DOM only when `version` changes.
- **Gear & attachments** (data in `weapons.js`: `GEAR`, `ATTACHMENTS`, `ITEM_WEIGHT`, `BASE_CAPACITY`): helmets / vests Lv1-3 stop a share of head / body damage and wear out (`armorAbsorb()` in `main.js`; `dealDamageToPlayer(..., kind)` with `"head" | "body" | "blast" | "monster" | "raw"`), backpacks add capacity. Attachments change the held gun's stats through `weaponStats(id, att)` (`src/items/ItemDefs.js`, cached per combination; `currentDef()` returns it): optic zoom / aim spread, recoil, bloom, magazine, and the suppressor (quieter for monsters' hearing and other players' ears, `shot.s`). `ItemDefs.ITEMS` is the data-driven catalog (type, group, weight, rarity, slots) the UI reads. `Soldier.setGear(levels)` toggles helmet / vest / backpack meshes fitted to the model at load (measured off the rest pose in the torso's own frame, attached to the head / chest bones); teammates get `st.g` (helmet·100 + vest·10 + backpack).
- **`LootActions`** (`src/inventory/LootActions.js`) is the one place items move: `check(src, dst)` (pure, for drag highlights) and `move(src, dst, qty)`, `pickup(entry, opts)`. Walk-over, E and the inventory screen all use it. Every operation is all-or-nothing; anything displaced (a swapped helmet, a replaced scope, the rest of a stack you can't carry) becomes real ground loot via `spawnLoot`, never lost. Shared loot (any pickup with a network id) is claimed from the host first (`claim` → host `take { i, by }` / `deny`; `takenLoot` on the host, cleared each battle royale match), so two players can't take one item. Drops are shared in co-op too (`spawnShared`, `packLoot` / `unpackLoot`: `a` ammo, `m` attachments, `c` count, `d` durability).
- **Inventory screen** (Tab, `src/ui/LootScreen.js` + `loot-screen.css`): vicinity (`pickups.near()` within `VICINITY`), backpack with capacity bar, a live 3D character (`CharacterPreview`: a second `Soldier` in its own scene and renderer, loaded at boot, rendered only while open, drag to turn), gear slots, and gun cards with attachment slots. Pointer-event drag and drop (ghost, green / amber swap / red targets with the reason), double-click quick actions, right-click menu (use, equip, attach to…, drop, drop some…, inspect), Shift-drag or "…" for a quantity. It reads the real state and re-draws a panel only when `inventory.version` or the vicinity signature changes.
- **`Pickups`** (`src/pickups/`) keeps pooled world pickups per kind. Loot lies on the ground (guns, attachments, vests and backpacks on their side) at a fixed random heading, with a white inverted-hull outline (one extra InstancedMesh per kind) instead of light beams and rings. Entries are created on first need and hidden (not removed) on release; each spawn gets a fresh `uid` (stale UI rows can't take a reused entry) and `pending` while claimed from the host. `lockAuto(entry)` (every drop of yours) stops walk-over pickup until you've stepped out of reach once, or you'd walk your drop straight back into the backpack. Kinds with `interact` (guns, gear, attachments) need **E**; ammo, throwables and medkits are collected by walking over them. World loot is placed deterministically in `spawnWorldLoot()` (`main.js`), skipping spots over colliders, and zombies roll `DROP_TABLE` on death (timed drops).
- **`Throwables`** (`src/combat/Throwables.js`) uses a pool of physics projectiles (`GROUP_PROJECTILE`: hits world and zombies, passes through the player). Grenades explode on a fuse. Molotovs shatter on the first `collide` and leave a fire zone, with a scorch decal and a persistent light. Damage reaches `main.js` through `onExplode` / `onFireTick`. Hold **G** to show the trajectory arc and release to throw; **Q** switches type. Grenades cook: the fuse (`GRENADE.cookTime`, 5 s) starts with the pin, `#grenade-cook` counts 5…1 under the crosshair, the throw carries the time left (`f` in the `throw` message), and holding to the end bursts it in your hand.
- **First person indoors**: inside a house (`houses.houseAt`, not driving / climbing / airborne) `fpBlend` eases the camera into the soldier's head (`applyFirstPersonCamera()` after `updateSoldier`, from `soldier.getHeadWorldPosition()` + `FP_EYE_UP` / `FP_EYE_FWD`); `soldier.setFirstPerson()` hides the head and helmet, the gun is held up so the hands show, the near plane drops to `FP_NEAR`, and the FOV is `cameraRig.fp` (narrowing with the aim).
- **Scopes**: guns with `scope` (the sniper, or any gun with the 4x ACOG) go past the shoulder aim into a first-person scope (`scopeBlend`, `cameraRig.scope`, `#scope-overlay`): your body hides, the FOV drops to the gun's `aimFov`, and the look speed scales with the zoom. The zoomed view fills the screen (PUBG / Free Fire style): the overlay is a mil-dot reticle, a faint lens ring and an edge vignette, never a black mask.
- **Weapon wheel** (`src/ui/WeaponWheel.js`): the mouse wheel opens a 3D ring of weapon cards around the player (after React Bits' Circular Carousel; DOM + CSS transforms, spring snapping, cards bend with the spin). Scroll turns it, left click or 1.3 s idle equips, right click cancels. In solo, while it's open and a monster is chasing within 40 m, the world runs at `timeScale` 0.2 (`animate()` scales `delta`; the camera uses `realDelta`).
- `Soldier.setWeapon(id)` swaps the held model and muzzle. The procedural guns sit on the SMG's grip point.
- **`FireFX`** (`src/combat/FireFX.js`) is GPU fire and smoke modelled on three.js `webgpu_particles`, written as a WebGL `ShaderMaterial` on instanced billboards. Each particle's whole life (rise, drift, spin, grow, colour ramp, fade) is computed in the vertex shader from one shared time uniform and per-instance random attributes, so the CPU only moves emitter centres. It has pooled `ground` (molotov puddle), `body` (burning zombie), and one-shot `blast` (grenade) emitters. The shaders include the logdepth and fog chunks.
- **Smoke grenades** (`THROWABLES.smoke`, `SMOKE`, `SMOKE_COLORS`): battle royale loot (field + house) and 2 in the warm-up kit. It pops after `SMOKE.fuse` into a coloured cloud from **`SmokeFX`** (`src/combat/SmokeFX.js`, pooled instanced billboards animated in the vertex shader like FireFX; the colour index is picked by the thrower and sent as `c` in `throw`). `smokeFX.blocks(a, b)` hides enemy name tags behind / inside smoke (`remotePlayers.concealed`), and `density()` drives the `#smoke-overlay` tint when the camera is inside a cloud.
- Burning: `ZombieManager.ignite(zombie, seconds)` sets `burnTimer`. Burning zombies take `BURN_DPS` after leaving the flames, switch to the charred `burnMaterial`, and corpses smoulder. `FireFX.syncBodies()` keeps a body emitter on every burning zombie.
- `Effects` keeps a small CPU flame buffer (the flying molotov rag) plus the explosion flash sprite and one persistent light.

### Towns & roads (`src/world/Towns.js`, `src/world/Roads.js`)

- **The bigger island**: the Highway and the North Road run on to the coast (`toShore()` pulls open roads' ends to `END_INLAND` short of it). The **Outer Ring** (closed, ~360 m out) links the new villages: Machhiwada (a fishing village of huts on the west coast, `kinds: COAST_KINDS`, with beached boats from `Water.buildBoats`), Rampur, Sonapur, the hill village Pahadi, and farmsteads. A town can set `kinds` to override `KIND_WEIGHTS`. `VEHICLE_SPAWNS` gained the city's and villages' vehicles (appended: indices are on the wire).

- **Layout** (`Towns.js`): `ROAD_DEFS` (Highway E–W, North Road N–S, a closed Ring Road) and `TOWNS` (Crossroads round the spawn, Ravencross, Ashford, Mill Creek, Pine Hollow, plus unnamed farmsteads). `layoutTowns()` (seeded, identical for every player and preset) lines each town's roads with houses of all three kinds, doors toward the street, skipping caves, the spawn, props and other roads, and walls some neighbours into yards (gate in front of the first house's door). Each town sits on a level plateau (a terrain pad with its own `y`); `flatHeight(x, z, pads)` gives the ground before roads. `townLabels` go on the world map.
- **Roads** (`Roads.js`): Catmull-Rom centrelines sampled every 3 m with a grid for `nearest()` / `distance()` / `onRoad()`. `setProfile()` eases each road's height along the ground and holds it level through towns; `modify()` levels the terrain under the asphalt + `SHOULDER` and blends back, `tint()` paints dirt shoulders (both passed to `buildTerrain`). One merged asphalt mesh (canvas texture: edge lines, dashed centre line; roads stacked a hair apart where they cross). `buildPoles()`: power poles every 34 m (one InstancedMesh + one for transformer drums), three sagging wires per span (one LineSegments), a cylinder collider and a minimap dot each; none at junctions, in yards or against houses. Trees, rocks, the forest and loot spots keep off roads and yards. The minimap and world map draw `roadLines`.

### Houses (`src/world/Houses.js`)

Enterable houses in three kinds (`HOUSE_TYPES`: the two-storey `house`, a one-storey `bungalow`, a 4 × 4 `cabin`; each with its own walls, furniture, lamps, switches and `loot` spots), built from Kenney's CC0 Building Kit (kenney.nl/assets/building-kit, the full kit has stairs, low walls, trims and detailed windows) and Furniture Kit. The source GLBs and licences are in `public/models/house/source/`, and `npm run build-house-kit` packs them into one `house-kit.glb` (top-level nodes `b_<piece>` / `f_<piece>`; the door keeps its `open` / `close` clips).

- Ground floor: living room + kitchen, door on +Z, stairs (`stairs-closed`) along the back wall climbing toward −X. Upper floor (`WALLS_UP`, surface `UP_Y`): windows on nearly every segment for camping and shooting out, a railing round the stairwell (`HOLE`, `RAILING`). Furniture, lamps (`CEILING_LAMPS` [x, z, floor]) and `HOUSE_LOOT_SPOTS` [x, z, floor] carry a floor index; `lootSpot(h, spot, out)` gives world x/y/z.
- `add(x, z, rot, { type, base, tint })`: every house of a kind shares its layout; `base` is the ground height (towns sit on hills) and `tint` multiplies the textured walls. Kit pieces are converted to plain Float32 before merging (newer exports are quantized). **Rendering is instanced** (`finalize()` once after every add): per kind one InstancedMesh per material for the shell (walls, floors, roof, glass) and for the interior (furniture, lamps, switch plates), plus shared ones for the door parts (copied from each house's hidden animated door clone), the bulbs (instanceColor on / off) and the switch rockers. `cull(camera)` each frame packs in the houses in view (and all within `NEAR_ALWAYS` for shadows), interiors only within `INTERIOR_RANGE`, and rewrites the buffers only when that set changes or a door moves; `warmup()` shows everything for the loading-screen compile. Houses are scaled ×`HOUSE_SCALE` (1.2) so 2.4 m zombies fit through doors and under ceilings. `_toLocal()` / `_toWorld()` convert between world metres and kit units, and all layout constants are in kit units; `lootSpots(h)` gives a house's spots.
- **Yards** (`addCompound(x, z, rot, hw, hd, gateX, base, tint)`): 1.8 m walls round a group of houses with a gate in the front (road) wall; one static body each, instanced panels + piers, thin boxes in `mapObstacles` (the rickshaw can't drive through), `inYard()`. `navigate()` routes monsters in or out only through the gate, and when several obstacles cross a monster's line it detours round the nearest one (allocation-free).
- Physics: one compound static body per house with a 0.4 m thick box per wall section (doorway jambs plus lintel; windows framed). Window holes are separate `GROUP_GLASS` bodies: they block the player and zombies but not bullets, grenades, the camera or grenade blasts. The door leaf is a kinematic box synced from the animated `door` node. Furniture gets oriented boxes. Everything uses the frictionless `staticMaterial`.
- Interaction: **F** opens / closes the nearest door (ground floor only; plays the kit clip; reversing mid-swing mirrors the time). **L** toggles the light switch of the floor you're on: `h.floors[i]` = { lightOn, lampMat, lever, switchWorld }, `toggleLight(floor)`, net `light { h, f, on }`, `world.lights` is per house [ground, upstairs]. The shared point lights (`QUALITY.houseLights`) go to the nearest lit floors. `interaction(x, z, feetY)`, `level(h, feetY)`, `floorAt(x, feetY, z)`. Prompts are shown through `InventoryUI.setPrompts()`.
- Stairs: the player walks a tilted box (ramp) collider plus a solid block under the high half; the ground snap steps up ledges (`STEP_UP`). The ramp is a separate body with `collisionFilterMask: ~GROUP_ZOMBIE`: monsters are pinned to `surfaceAt(x, z, feetY, terrainY)` (stairs with a 0.45 m lead, upper floor when already up there, else ground) via `ZombieManager.surfaceAt`, and `navigate(..., zy, ty)` routes them to the foot / top of the stairs and round the stairwell. Melee needs the target on about the same level.
- Zombie pathing: `ZombieManager.navigate` is set to `houses.navigate()`, re-planned every 0.15 s per zombie. Zombies route around houses and editable props (`navObstacles`) via corner waypoints, line up with the doorway before walking through, and at a closed door return `2`: they bang on it (`onDoorBang` sound) and never attack through walls. `canSpawnAt` keeps spawns out of houses. `doorAssist()` nudges the player toward the door centreline.
- Grenade damage is shielded (×0.15) when a `GROUP_WORLD` ray from the blast to the target is blocked.
- Climbing and vaulting (`climb` in `main.js`): `houses.windowVaultSpot()` offers SPACE "Jump through the window" when you face a window whose sill is knee-to-chest high (upstairs ones from inside: out you drop); `houses.wallClimbSpot()` offers "Climb over the wall" after `CLIMB_WAIT` (2 s) facing a yard wall (not the gate gap). Either is a short scripted move with `collisionResponse` off (`updateClimb` / `climbAfterStep`), then gravity.

### World map & pins (`src/ui/WorldMap.js`, `src/ui/Waypoints.js`)

- **M** or the touch map button opens `WorldMap` in every mode (`setMapOpen()` in `main.js`): a shaded-relief picture of `groundHeight` (rendered once, on first open), buildings, trees, wrecks, the rickshaw, teammates and the BR overlays. Tap / click drops your pin, tapping it again lifts it; drag pans, pinch / wheel / ± zooms. With pointer lock the mouse drives a virtual cursor (`cursorMove` / `cursorButton` / `cursorWheel`), so the game never pauses.
- `setPin(id, x, z, share)` keeps `WorldMap`, `Waypoints` and the minimap's `pinList` in sync. Co-op shares pins (`pin` message, `c: 1` lifts it); the BR doesn't. Reaching your pin (4 m) lifts it.
- `Waypoints`: pooled light pillars at pins (always in the scene), on-screen distance markers clamped to the screen edge, and the compass tape at the top centre with every pin's bearing.

### Minimap (`src/ui/Minimap.js`)

A rotating radar on a 2D canvas, top right. It draws zombies (pulsing when chasing, orange when burning), pickups by category, fires, and obstacle footprints from `mapObstacles` (filled in by `addBoxCollider`, `addTreeCollider`, and live getters on editable models). Off-map weapons get edge arrows. It redraws at 30 Hz, not every frame. lil-gui is moved to the top-left in CSS.

## Performance Rules

- **Light pool** (`src/render/LightPool.js`): every point light is compiled into every lit shader and costs every lit pixel, so modules never add point lights to the scene. They `lightPool.adopt(light, priority)` their own (virtual) lights and drive them as usual; `lightPool.update()` (in `renderFrame()`) copies the best ones (priority × brightness × nearness) into `QUALITY.pointLights` real lights (Low 2, Medium 3, High 4, phones 2). Muzzle flash 2, blast 3, molotov fires 2, cave torches 1.5, wreck and house lamps 1.
- **Loot is batched**: `Pickups` draws every kind's matte parts, metal parts and outline through three `BatchedMesh`es (a fixed pool of `SLOTS` instances handed out each frame with `setGeometryIdAt`), so all ground loot is three draw calls; only glass parts keep an InstancedMesh per kind. Custom shaders on batched meshes must use `batchingMatrix` under `#ifdef USE_BATCHING`.
- **After the start**: the dragon (`MONSTER_TYPES.dragon.lazy`, `MonsterPool.loadLazy()`, `warmLazyMonsters()`) and the two big tree models (`plantTrees()`: positions, sizes and colliders are decided in `loadWorld()` from `TREE_MODELS`' measured sizes, so the layout never waits) download once the game runs, and their programs compile with `compileAsync` before they're shown. Don't `<link rel=preload>` them.
- **One sound request**: `scripts/pack-sounds.mjs` (npm `prebuild`) packs `public/sounds/*.ogg` into `pack.bin` + `pack.json`; `Sfx.preload()` slices it (falls back to the separate files).
- **Spatial grids** (`src/world/SpatialGrid.js`): point queries during world generation (`houses.blocks` / `inYard`, `farmland._inField` / `inCane`, `plots._at`, `city.buildingAt`, `nearObstacle`, the terrain pads in `flatHeight`) read one grid cell instead of scanning every item. `shoreRadius()` is a 4096-entry table by angle. `quality.js` caches the GPU name in localStorage (no throwaway WebGL context per load).
- **Dynamic resolution without reallocating**: with the grade pass (`PostFX.canScale`: post on, no bloom) the render scale only moves the viewport / scissor the scene draws into inside the full-size target (`setScale`, `uScale` in the grade shader); the canvas is resized only without it.
- `?perf=1` `LOAD_MARKS` include `· …` sub-phases of `loadWorld()` (towns, city / fields / plots, terrain, water, caves, trees / rocks).

- **Physics broadphase:** `StaticGridBroadphase` (`src/physics/`): the ~520 static bodies sit in a 16 m grid built once (re-gridded when a static body is added / removed or sets `aabbNeedsUpdate`; its flag is `_gridDirty` because cannon sets `broadphase.dirty` every step); each step only awake dynamic bodies query the grid, and moving bodies are paired among themselves when one is dynamic. Raycasts (`aabbQuery`) use the grid too. It replaced SAP (5+ ms a step → ~0.4 ms, same pairs). Pairs are confirmed by bounding boxes, and every static body sits at its own centre: a mesh with world-space vertices on a body at the origin has an AABB / sphere covering everything (the cave colliders did, which cost half the CPU).
- **Empty instanced meshes are hidden:** three.js issues a draw call (and a shadow one) for an InstancedMesh with `count = 0`, so pickups (one per item kind × material + outline), house parts (`_commit`) and blood stains set `visible = count > 0`.
- **Dynamic resolution** counts logic + draw submission as CPU time (`updateDynamicResolution(frameMs, cpuMs)`): CPU-bound frames keep full sharpness. A raise that gets taken back within 8 s doubles the wait before the next (each change reallocates the canvas and post targets).
- **Loading screen** (`index.html`, styled inline so it paints before the stylesheet and scripts): the town art (`public/loading/town-hd.webp` / `town-960.webp`, made from the PNG; a 400-byte blurred placeholder is inlined until it decodes), slow drift + mist, rotating tips (inline script), and one bar for the whole load: downloads fill 72% (`DefaultLoadingManager.onProgress`), then each `loadMark()` phase moves it on and sets the status (`LOAD_STAGES`).
- **Fast loading:** the biggest models are `<link rel="preload" as="fetch" crossorigin>` in `index.html` (low priority, same request mode as three's loaders), so they download while the scripts parse; meshopt decoding runs on workers (`MeshoptDecoder.useWorkers`); the cave rock is built in a worker (`world/cavesWorker.js` → `adoptCavesData`, falling back to `precomputeCaves()` on this thread); sounds start after the models; India models fetch the `.opt.glb` directly (no HEAD first); the old free rickshaw is only fetched if the Indian one is missing; the warm-up compiles monster hit / burn variants per monster (`compileAsync(object, camera, scene)`), not as 16 more full-scene passes. Production builds register `public/sw.js` (cache-first for `/assets/`, stale-while-revalidate for models / trees / textures / sounds / loading art, network-first for the page; the first visit's files are handed to it), so a second visit loads from the device. Bump its `VERSION` to drop the cache.
- **Loading:** `renderer.debug.checkShaderErrors` is off in production (it waits on every program's link status one by one); item icons only render 3D silhouettes the icon set lacks; `?perf=1` prints `LOAD_MARKS` (ms per boot phase) to the console. Pooled monsters leave the physics world while parked (`MonsterPool._deactivate`). At most 2 physics sub-steps a frame.
- **No layout reads or text rasterising per frame:** cache canvas / element sizes (re-read on `resize`), pre-render canvas text (the minimap compass letters) instead of `fillText` each redraw.
- **Hidden parts leave the hierarchy:** `Soldier` takes hidden guns and gear off their bones (`showPart`) instead of only hiding them; hidden objects still cost a matrix update every frame (×100 players in the BR).
- **Measure first:** `?perf=1` shows the profiler overlay, `?bench=1` runs the scripted benchmark (`src/debug/PerfOverlay.js`, `startBenchmark` in `main.js`). See PERFORMANCE.md for the phone procedure and the last measurements.
- **Trees use LOD:** `npm run optimize-assets` also writes `public/trees/*.lod1.glb` (~20% of the triangles, no textures); scattered trees are a `THREE.LOD` switching at `TREE_LOD_DIST`, drawn with the full model's material. `?lod=0` disables it for A/B.
- **Pickups are instanced:** one InstancedMesh for all beams, one for all rings, and per item kind one per material class (metal / matte with baked vertex colours / glass). House furniture shares one vertex-coloured material.
- `warmUpGpu()` widens the shadow camera to the whole map and shows every LOD level for its render, so no shadow-depth program compiles mid-game.
- Phones: frame cap `frameCap()` (touch setting Auto / 60 / 30; Auto settles on 30 when 60 can't be held at the lowest render scale), pause + audio suspend on `visibilitychange`, reload on WebGL context loss.

- **Assets:** run `npm run optimize-assets` after adding or replacing a heavy model. `loadGLB()` loads `<name>.opt.glb` (meshopt-compressed, simplified, WebP textures) and falls back to the original. The script's `prune: true` mode uses meshoptimizer's Prune flag with a sloppy fallback for foliage triangle soups (the trees went from 6.3M to about 250k indices).
- **Loading:** the soldier, zombies and world download in parallel. `warmUpGpu()` compiles every program while the loading screen is up, so nothing compiles mid-fight. That includes the zombie hit and burn materials, the fire shaders, and each monster type's shadow-depth program (one of each stands near the player for the warmup render). Lights that toggle (flashlight, firelights) stay in the scene at intensity 0 for the same reason.
- **Rendering:** no `logarithmicDepthBuffer` (it kills early-Z). Dynamic resolution (`updateDynamicResolution`) scales the pixel ratio between about 0.65 and min(dpr, 1.5) based on frame time. Static props and ground chunks call `freezeStatic()` (`matrixAutoUpdate = false`). Pickups don't cast shadows. At most 2 fire point lights, shared across molotov fires.
- VRML imports: strip the `Background` sky spheres (radius 10000), or they swallow the bounding box and collider.
- **cannon-es `Cylinder` is Y-aligned.** Don't rotate it 90° on X (old cannon.js habit): that lays capsules and tree trunks sideways.
- cannon `Box` collides with its convex polyhedron: after changing `halfExtents` call `updateConvexPolyhedronRepresentation()`. `createEditableModel()` does, and supports `perMeshColliders` (the WRL house) and `trunkCollider` (trees).
- **Draw calls are the phone bottleneck.** Static multi-part models go through `mergeStaticMeshes()` (`src/world/MergeStatic.js`: one mesh per material, after colliders are measured). Transparent `DoubleSide` materials need `forceSinglePass: true`, or three.js draws them twice and re-resolves the shader every frame (`warmUpGpu()` sweeps loaded models). Pickups past `MODEL_RANGE` aren't drawn.
- Parked pool objects set `matrixWorldAutoUpdate = false` (monsters, their markers, pickups) so the scene's matrix update skips them. The scene's matrix update is replaced by `updateVisibleMatrices()` (skips hidden subtrees); it must also refresh `SkinnedMesh.bindMatrixInverse`, or skinned GLBs draw offset by their parking spot. The physics world uses `ObjectCollisionMatrix` (the default array one is n²/2 and cleared every step).
- **No per-frame heap allocation** in hot loops — reuse `THREE.Vector3`, `CANNON.Vec3`, etc.
- **Zombie pool only** — never `scene.add()` / `scene.remove()` per spawn/death.
- **AI distance tiers**: run full AI logic only for zombies within ~15 m; reduce update frequency at 15–40 m; skip or sleep at 80 m+.
- **HUD DOM** — only update when the displayed value actually changes.
- Shared geometry and materials across zombie instances; shared chunk geometry across ground tiles.
- Shadow map is 1024×1024; shadow frustum tracks the player (or whoever you spectate, `focusPos`) rather than being world-wide.
- Respect `QUALITY` (src/quality.js) for anything visual and costly; keep collider-bearing content identical across presets.
- Anything placed on the ground uses `groundHeight(x, z)`; GPU effects sample the terrain texture with `TERRAIN_GLSL`.
